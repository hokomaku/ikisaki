# 行先表示 撮影記録（GitHub Pages + Supabase）

スマートフォンを主な利用端末とした、個人・家族用の行先表示撮影状況トラッカーの初期環境です。写真ファイルや撮影日時は保存しません。

## 重要な構成判断

GitHub Pages は静的サイトの配信先であり、非公開データベースや安全なログイン機能を単独では提供しません。このため、フロントエンドは GitHub Pages、認証・データ保存は Supabase を使用します。GitHub Pages のURL自体は知っている人なら開けますが、データ操作は Supabase Auth でログインした利用者に限定する設計です。

このリポジトリには Supabase の公開用 anon/publishable key だけを設定します。`service_role` キーをブラウザや GitHub Actions の公開ビルドへ入れてはいけません。RLS は必須です。

## セットアップ

1. GitHub で新規リポジトリを作成し、このフォルダの内容を `main` ブランチへ push します。
2. Supabase でプロジェクトを作成します。
3. Supabase の SQL Editor で `supabase/schema.sql` 全文を実行します。
4. Supabase Auth の設定で **公開サインアップを無効化** し、使うアカウントだけを管理画面から作成します。家族も使う場合は、同じアカウントを共有するより個別アカウントを作る方が、後からアクセスを取り消せるため安全です。この初期版ではログインユーザーは全員同じ権限です。
5. Supabase の Project URL と publishable/anon key を取得します。
6. GitHub リポジトリの **Settings → Secrets and variables → Actions** に次の Repository secrets を登録します。
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
7. GitHub の **Settings → Pages → Build and deployment** で **GitHub Actions** を選びます。
8. `main` へ push するか Actions から `Deploy to GitHub Pages` を実行します。
9. デプロイ後、GitHub Pages のURLを開いてログインします。

ローカルで試す場合は `.env.example` を `.env` にコピーして値を設定し、`npm install`、`npm run dev` を実行します。

## 初期版に含む機能

- 所属会社・形式・種別マスタの追加
- 形式ごとの次駅表示フラグ
- 定期行先の複数行一括追加（次駅表示あり形式なら「あり／なし」を自動で作成）
- 定期外・消滅対象の個別追加
- 撮影状況のクイック変更（未撮影／済み／再履修）
- コメント、曜日、時間帯条件
- 会社、形式、種別、行先、撮影状況、定期区分、次駅、曜日、時間帯のAND検索
- 現在の絞り込み結果に対する定期行先進捗率（済み＋再履修／定期件数）
- CSV書き出しと再インポート（種別マスタは対象外）
- スマホ向けレイアウト

## 仕様として未確定／この初期版で仮決めしたこと

1. **次駅フラグを「なし」に変えた場合**：既存の次駅あり／なしレコードを自動削除しない方針はSQL側では強制していません。UI上では形式フラグを切り替えます。既存対象は `next_station` 値を保持します。表示・編集の扱いは今後テストして確定してください。
2. **次駅フラグを「あり」に変えた場合**：既存の次駅なし形式の対象から、あり／なしの2件を補完します。既存の対象は残し、足りない組み合わせだけ追加します。補完分の撮影状況は元対象と同じにします。
3. **定期行先の一括追加**：1行に「種別マスタ名＋行先」を入力し、登録済み種別マスタの名称と先頭一致する最長の種別名で自動分割します。種別名で始まらない行はエラーにします。
4. **重複判定**：形式＋種別＋行先＋区分＋次駅状態で重複を防止します。定期外・消滅は区分が異なるため、定期対象と同じ表示でも別レコードにできます。
5. **CSV再インポート**：既存IDを更新し、IDなしの行は複合キーで照合して更新、該当がなければ追加します。CSVから行を消してもデータベース側の行は削除しません。全件削除を伴う同期は誤操作リスクがあるため初期版では行いません。
6. **認証**：初期版はメールアドレス＋パスワードです。指紋認証（パスキー/WebAuthn）は未実装です。端末の生体認証だけでサイト側の認証を完結することはできず、別途パスキー対応が必要です。
7. **アカウントと家族**：初期版はログイン済みユーザー全員に同一権限を与えます。家族が各自のアカウントを持つことを推奨します。共有アカウントも技術上は可能ですが、個別にアクセスを止められません。
8. **進捗率の表示単位**：初期版は現在の検索結果に対する進捗率を表示します。会社・形式・親ページ単位の階層ダッシュボードは今後の改善項目です。
9. **形式・会社の変更**：初期版では形式の名前・所属会社を変更できます。形式名が変わってもIDで関連付けるため、撮影状況は維持されます。会社名変更専用の編集UIは未実装です。
10. **定期から消滅への変更**：撮影状況を変更せず区分だけ変更するUIは未実装です。初期版では対象編集画面から区分を変更してください。
11. **定期行先の削除**：確認ダイアログを出して物理削除します。削除後の復元機能はありません。
12. **データ規模・ページネーション**：初期版は全件取得を前提にしています。件数が数千件以上になったらページネーションやサーバー側集計を検討します。
13. **運用上の制限**：初期版は認証・基本CRUDの土台です。公開前に、RLS、重複登録、次駅フラグ変更、CSVの再インポート、スマホ実機での動作を検証してください。

## CSVの主な列

`id, format_id, format_name, company, category_id, category, destination, record_type, next_station, status, comment, weekdays, time_bands`

- `next_station`: `あり` / `なし` / 空欄
- `weekdays`, `time_bands`: `|` 区切り
- IDを残したまま編集すれば同じ対象を更新できます。
